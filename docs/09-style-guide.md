# Style guide

Minimal and developer-centric, as a Notion page or a GitLab README would look.

## Typography
- Body: Inter or Roboto (clean sans-serif).
- Code, YAML, SQL, file paths: monospace.

## Layout
- Short sentences. Simple markdown tables, blockquotes, bullets.
- One message per slide or section. No decorative templates.
- Diagrams: plain boxes and arrows, text only.

## Colors
Use the prototype's tokens (VORO-style) when a color is needed: neutral greys, one accent, green for success, amber for waiting. Check `web/tailwind.config` for exact values. Light and dark must both read well.

## Tone
Pragmatic, technical, confident. Preferred words: governance, traceability, one definition, review, rollback. Avoid hype.

## Labels
Mark claims as **Built**, **Prototype**, **Proposed** or **Unverified**. Never state a number without a source.

## Names
Jean, Noa and Ravi are demo characters. Use the roles ("business user", "data analyst", "data engineer") in external material.
